**`MANIFEST` is NOT in the tarball.** Measured: `cat .../MANIFEST` →
`NO MANIFEST FILE`, and the member list above is the complete archive. The
manifest that exists on the production host is generated by the installer, not
shipped (§2). `example.env` **is** shipped in the tarball, 77 503 bytes; the
local checkout's `example.env` is 85 837 bytes, so that file has grown since the
release commit — the tarball's copy (not the checkout's) is the reference for
this build. The example env was read for the variable names the binary honours,
not hashed.

Note: on 0.10.0 `/api/auth/status` returns **four** fields, not the two quoted in

(`initialized:false, admin_count:0`) is an oracle that must not be probed: any
valid setup payload would create the first admin irreversibly.

## 3. Postgres

| | sandbox (tests) | production (reference) |
|---|---|---|
| server | PostgreSQL 18.2 on x86_64-pc-linux-musl | PostgreSQL 17.11 (Debian 17.11-0+deb13u1) |
| image / package | `postgres:18.2-alpine3.23` (id `sha256:035b9ab53cfa147d7202b61f5f7782b939ae815b7d6bc81c96b7b42ff1fca950`) | Debian package, `/usr/lib/postgresql/17` |
| listen | `127.0.0.1:55432` (container) | `127.0.0.1:5432`, `[::1]:5432` |
| extensions present | `citext`, `ltree`, `pg_trgm`, `plpgsql` | not observable from the unprivileged account |

The 18.2 choice is the ticket's (matches this repo's `docker-compose.yml`); it is
a **deliberate major-version difference from production's 17.11**. Nothing in the
setup path uses a feature that differs between those majors (plain
`INSERT … ON CONFLICT DO NOTHING`, `SELECT`, `DELETE`), and every finding below
is stated for the sandbox's 18.2 with the production major noted.

Migrations: the app applied **112** migrations to the template DB
(`SELECT count(*) FROM _sqlx_migrations WHERE success` = 112). The harness never
creates schema by hand — the template DB is produced by booting the binary once,
so the schema under test is the binary's own.

Statement-log oracle (every statement the process issues is captured):

```
$ docker run -d --name re-pg -p 127.0.0.1:55432:5432 \
    -e POSTGRES_USER=re_user -e POSTGRES_PASSWORD=RE_PGPASS -e POSTGRES_DB=re_oxicloud \
    -v /data/re-scratch/pglog:/pglog postgres:18.2-alpine3.23 \
    -c log_statement=all -c log_min_duration_statement=0 \
    -c logging_collector=on -c log_directory=/pglog -c log_filename=postgresql.log \
    -c log_line_prefix="%m [%p] " -c timezone=UTC -c log_connections=on

$ docker exec re-pg psql -U re_user -d re_oxicloud -tAc 'show log_statement'
all
$ docker exec re-pg psql -U re_user -d re_oxicloud -tAc 'show log_min_duration_statement'
0
```

`log_connections=on` is on so connection churn (pool checkout) is visible too.
The harness's own probes are tagged `/* RE_PROBE */` so they are filtered out of
every reported statement window.

## 4. The sandbox instance under test

Binary: `/data/re-scratch/oxicloud-0.10.0-x86_64-unknown-linux-musl/oxicloud`
(the sha256 in §1).

Recorded env file (`/data/re-scratch/run-A/env.sh`, verbatim — the password is
recorded as the literal `RE_PGPASS`):

```
# effective environment — password replaced by RE_PGPASS before record
OXICLOUD_DB_CONNECTION_STRING=postgres://re_user:RE_PGPASS@127.0.0.1:55432/re_case_A
OXICLOUD_STORAGE_PATH=/data/re-data/A
OXICLOUD_SERVER_HOST=127.0.0.1
OXICLOUD_SERVER_PORT=18086
RUST_LOG=debug
```

Release posture: **no `OXICLOUD_RATE_LIMIT_*` variable is set**, so the shipped
defaults apply. Read back from the instance's own startup line:

```
2026-11-12T14:14:58.266050Z  INFO oxicloud: Rate limiting enabled — login: 10/60 s, register: 5/3600 s, refresh: 20/60 s
2026-11-12T14:14:58.165716Z  INFO oxicloud::interfaces::middleware::trusted_proxy: trusted proxy CIDRs: none — X-Forwarded-For/X-Real-Ip headers will be ignored
```

So in release posture: register **5 per 3600 s** (shared by `/api/setup`, as
case 13 measures), login 10/60 s, refresh 20/60 s, and **no trusted proxies**.

Runtime identity checks against the live sandbox instance:

```
GET /api/version     -> 200 {"name":"OxiCloud","version":"0.10.0"}
GET /api/auth/status -> 200 {"initialized":false,"admin_count":0,...}
```

### Measured release deviation: `DATABASE_URL` is ignored

`DATABASE_URL` alone does **not** point this release at a database:

```
$ env DATABASE_URL=postgres://re_user:RE_PGPASS@127.0.0.1:55432/re_oxicloud \
    ./oxicloud
INFO oxicloud::infrastructure::db: Initializing PostgreSQL connections with URL: postgres://postgres:redacted@localhost:5432/oxicloud
ERROR ... pool timed out while waiting for an open connection
```

`OXICLOUD_DB_CONNECTION_STRING` is the name this binary honours. (The local
checkout's HEAD additionally accepts `DATABASE_URL` as a deprecated fallback —
that fallback is **not** in the 0.10.0 release binary. Recorded because it
changes how the instance must be booted, and because it is a real release-vs-HEAD
drift the differential agent should not trip over.)

## 5. Secrets

* The Postgres password in this sandbox is a throwaway value for a
  loopback-only container. It is not a credential, and it does not appear in this
  file, in `docs/re/evidence/*` or in `docs/re/runtime-evidence.md`: the harness
  writes `run-<label>/env.sh` with `RE_PGPASS` substituted and routes quoted log
  lines through `re_redact`.
* `JWT` secret, storage dir and DB are per-instance under `/data/re-data/<label>`
  and `/data/re-*`; all request bodies use synthetic `*.example.test` addresses.
* Nothing in this report came from the production database or from
  `/etc/oxicloud/oxicloud.env`.
